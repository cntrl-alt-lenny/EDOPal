# EDOPal packs

Heavy media lives in [cntrl-alt-lenny/edopal-packs](https://github.com/cntrl-alt-lenny/edopal-packs),
not in the app. The app downloads a pack the first time the user picks it, verifies it, and keeps
it in the per-user cache (`<cache>/packs/<id>/`).

## Repository layout (edopal-packs)

```
catalog.json                 # generated by tools/build_catalog.py; also uploaded to the "catalog" release
themes/<slug>/               # source folder of a theme pack  -> theme-<slug>.zip
cardbacks/<slug>/            # one card back per pack          -> cardback-<slug>.zip
music/<slug>/                # one game soundtrack per pack    -> music-<slug>.zip
formats/                     # generated era banlists          -> formats.zip (single pack)
art/<slug>/                  # artwork collection              -> art-<slug>.zip
icons/<slug>/                # game icon set                   -> icons-<slug>.zip
thumbs/<pack-id>.webp        # small tile images (<= 480 px long side, < 60 KB), served raw
previews/<pack-id>.*         # optional larger preview (theme: 1280x800 webp; music: 20 s ogg clip)
tools/                       # build_catalog.py, build_zips.py, checks
```

Releases: each pack version is uploaded as an asset of release tag `packs-YYYY.MM.DD` (or newer).
`catalog.json` is attached to the moving release tag `catalog`. During development the app can
read the local checkout directly (`edopal.core.fakes.LocalPacks`, `url` = relative path).
The production client also accepts a checkout through `GitHubPacks(paths.cache, local_dir=checkout)`.

## catalog.json

```json
{"schema": 1, "generated": "2026-11-25T12:00:00Z", "packs": [
  {"id": "theme-abyss", "kind": "theme", "name": "Abyss", "version": "1.0.0",
   "url": "https://github.com/.../theme-abyss-1.0.0.zip", "size": 31457280,
   "sha256": "<hex>", "thumbnail": "https://raw.githubusercontent.com/.../thumbs/theme-abyss.webp",
   "preview": "", "meta": {"accent": "#7fb4d8", "tagline": "Deep-sea blues"}}
]}
```

The catalog's `size` and `sha256` describe the exact bytes of the ZIP asset. The manifest's
`files` hashes describe the uncompressed contents of its individual files. A local catalog
can point directly to a pack directory, where the same manifest hashes verify the contents.

`meta` carries kind-specific fields so the app can render tiles before downloading:
- theme: `accent`, `tagline`, `previews` (list of 3 preview image URLs: menu, deck, duel)
- cardback: `label` (e.g. "Yu-Gi-Oh! ZEXAL anime"), `era` (e.g. "2011"), `group` (one of
  `tcg-ocg`, `anime`, `manga`, `video-games`, `other-tcgs`), `default_for` (`"you"` | `"opponent"` | absent)
- music: `game`, `series` (when present in the manifest), `year`, `platform`, `track_count`, `duration_seconds`
- format: `formats` (count)
- art and icons use an empty `meta` object.

## manifest.json (at the root of every pack ZIP)

Common fields: `schema` (1), `id`, `kind`, `name`, `version`, `credits` (list of
`{"what", "source", "url"}`), `files` (map relative path -> sha256 for every other file).

### theme
```json
{"schema": 1, "id": "theme-abyss", "kind": "theme", "name": "Abyss", "version": "1.0.0",
 "tested_edopro": "41.0.2",
 "skin_dir": "skin",                      // copied to <game>/skin/EDOPal-<slug>/
 "font": {"text": "fonts/InterEDO-Regular.ttf", "size": 12, "num": "fonts/Inter-Medium.ttf"},  // optional
 "default_cardbacks": {"you": "cardback-vortex-classic", "opponent": "cardback-ocg-1998"},     // optional
 "previews": {"menu": "previews/menu.webp", "deck": "previews/deck.webp", "duel": "previews/duel.webp",
              "tile": "previews/tile.webp"},
 "accent": "#7fb4d8", "tagline": "Deep-sea blues", "credits": [...], "files": {...}}
```
Applying = copy `skin_dir` to `skin/EDOPal-<slug>/`, set `skin = EDOPal-<slug>` in
`config/system.conf`, optionally copy fonts into `fonts/` and set `textfont`/`numfont`. All via
`core.storage` so Undo restores the previous skin, fonts and conf lines.

### cardback
```json
{"schema": 1, "id": "cardback-vortex-classic", "kind": "cardback", "name": "Vortex",
 "version": "1.0.0", "label": "Yu-Gi-Oh! TCG (classic, no logos)", "era": "2002", "group": "tcg-ocg",
 "image": "back.png",        // 708x1016 PNG (177:254), what EDOPro loads
 "master": "master.png",     // optional full-resolution master (not copied into the game)
 "credits": [...], "files": {...}}
```
Applying writes `image` to `textures/cover.png` (you) or `textures/cover2.png` (opponent) in the
active EDOPal skin's `textures/` if an EDOPal theme is active, else the base `textures/`.

### music
```json
{"schema": 1, "id": "music-dawn-of-destiny", "kind": "music", "name": "The Dawn of Destiny",
 "version": "1.0.0", "game": "Yu-Gi-Oh! The Dawn of Destiny", "series": "Duel Monsters",
 "year": 2004, "platform": "Xbox",
 "cover": "cover.webp",
 "tracks": [{"id": "deck-1", "title": "Deck Construction", "path": "audio/deck-1.ogg",
             "duration_seconds": 142, "suggested_roles": ["deck"]}],
 "credits": [...], "files": {...}}
```

Roles map to EDOPro folders: menu -> `sound/BGM/menu`, deck -> `sound/BGM/deck`,
duel -> `sound/BGM/duel`, win -> `sound/BGM/win`, lose -> `sound/BGM/lose`. EDOPal writes its files
as `edopal-<pack>-<track>.<ext>`; it never deletes files it did not create without asking.

### Art

Art packs use `kind: "art"` and IDs starting with `art-`. The app fetches each collection on demand
and reads its images from the verified pack folder.

| Pack ID | Payload |
| --- | --- |
| `art-card-of-the-day` | `banners/<card-id>.jpg` at 1600×460 (JPEG quality 86), `thumbs/<card-id>.jpg` at 800×230, and `banners.json` with card IDs, first English TCG release details, source crops, and normalized focus points |
| `art-music-banners` | `banners/<music-slug>.jpg` at 1600×500, transparent `logos/<music-slug>.png`, and `credits.json` with per-game artwork sources |
| `art-archetypes` | `thumbs/<archetype-slug>.jpg` at 160×160, `wide/<archetype-slug>.jpg` at 480×270, and `archetypes.json` with deck names, representative card IDs, and single or split layouts |
| `art-format-heroes` | `<format-id>.jpg` at 1600×560 and a `cards` map in the manifest from format ID to hero card ID |

Derive archetype slugs by lowercasing the deck name, replacing runs outside `a–z` and `0–9` with a
hyphen, and removing leading and trailing hyphens. Each art pack with a separate JSON index points
to it in the manifest's `index` field.

Run `.venv/bin/python packs/tools/package_art.py` from the app checkout to regenerate the art packs.
Use `--pics /path/to/EDOPro/pics` to select a local scan directory. Then run
`.venv/bin/python packs/tools/build_catalog.py` to generate the archives and local catalog.

### Icons

Icon packs use `kind: "icons"` and the common inventory and credits fields.

| Pack ID | Files |
| --- | --- |
| `icons-stock` | Original EDOPro PNGs in `textures/`, stock credits, and `previews/field.webp`, a 620 × 430 crop from a captured duel |
| `icons-minimal`, `icons-minimal-gold`, `icons-minimal-glass` | Eleven replacement PNGs per preset in `textures/` |
| `icons-candidates` | Five alternatives per supported slot in `candidates/<slot>/A.png` through `E.png` |

Texture stems are `act`, `attack`, `chain`, `number`, `negated`, `target`, `chaintarget`, `equip`,
`lim`, `lpf`, and `settings`. Chain, chain target, and settings use the preset designs.
The editor displays a single cell from the number and restriction atlases.
Apply copies the complete PNG for each slot, including its alpha channel and all atlas cells.

From the EDOPal checkout, run `.venv/bin/python packs/tools/package_icons.py` to assemble the source packs.
Run `.venv/bin/python packs/tools/build_catalog.py` to generate the catalog and release ZIPs.
