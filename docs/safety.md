# What EDOPal writes and how to undo it

Check the EDOPro folder shown in EDOPal before applying a change. Close EDOPro before changing its appearance, audio or active configuration. Reopen the game after applying or undoing the change.

## Game-folder writes by feature

| Feature | What changes | Recovery |
| --- | --- | --- |
| **HD Cards** | Adds or replaces `pics/<id>.jpg` and `pics/field/<id>.jpg` or `.png`. The downloader checks new data before replacing a file. Force refresh, repair and a change to the GOAT/Pre-Errata artwork setting can replace existing images. Field repair can remove a broken alternate file after a successful replacement. The CLI’s `--prune` deletes orphaned JPEGs. Coverage leaves artwork alone. | For a newly added image, remove the specific file to reverse the addition. To recover any previous image after replacement or pruning, restore it from your own copy. The built-in backup ZIP excludes game pictures. [Artwork backend](../main.py) |
| **Skins made with the theme editor** | Publishes a managed folder under `skin/Studio-<id>`, updates owned keys in `config/system.conf` and keeps recovery information in `config/.edopro-studio-themes/`. Choosing Inter installs it inside the managed skin. | Switch back to restore the previous skin and its managed font settings. Undo reverses the last edit or first install. Remove deletes files the engine can verify it owns and preserves extra files. [Theme engine](../themes/README.md#game-operations) |
| **Legacy or downloaded skins** | Copies skin and shared font files into the game folder, then sets the active skin and font entries in `config/system.conf`. | Restore the previous appearance using the same app config. It restores the settings and can leave the copied skin and font files on disk. Restoring settings still works after clearing the download cache. [Appearance writer](../extras.py) · [Pack reference](content-packs.md#from-skin-selection-to-applied) |
| **Sleeves** | Writes player `cover` and opponent `cover2` textures in the game or active skin, as appropriate. A saved preference can be reapplied when EDOPal changes the skin. Designs and cached cropped art live in the companion’s library. | Undo the last sleeve change using the same app config. The engine checks for outside edits before overwriting textures during undo. [Sleeve installer](../sleeves/install.py) |
| **Sounds** | Publishes selected sound files under `sound/`, including card-specific chants, and removes alternate formats for changed slots. An explicit silence removes all supported formats for that slot. The optional sound switch changes one key in `config/system.conf`. | Undo the last set change or restore the recorded originals. Restore goes back to the first recoverable state for those slots. To reverse the separate on/off change, set the switch back to its previous value. [Sound engine](sounds.md) |
| **Music** | Changes the playlist under `sound/BGM/` for the selected scene. The duel playlist also manages loose tracks directly in `sound/BGM/`. The game’s saved tracks and playlist history live in `sound/.edopro-hd-sync/`. Enabling music changes one key in `config/system.conf` and preserves volume. | Undo the last playlist edit for the scene or restore the original playlist. Set the music switch back separately if you changed it. Keep the hidden playlist state with the game. [Playlist code](../music_library.py) |
| **Tournament decks** | Creates `.ydk` files under `deck/`, including a separate copy for historical Goat versions when selected. An existing edited deck is preserved. | The latest import receipt can undo unchanged copies during the same session. You can also remove a copy in your file manager. A separate artwork sync for the imported cards follows the HD Cards rules above. [Tournament importer](../tournament_decks.py) · [Import receipt](../studio/pages/decks_import.py) |
| **My decks** | Searching, comparison and legality checks read local files. Saving a reviewed sharing code or repair creates a fresh `.ydk` in `deck/`. | Remove the new copy. Your source deck remains available. [Deck sharing and repair](../decks/sharing.py) |
| **Replays** | Preserving the last replay creates a separate file under `replay/`. The rolling recording stays in place. Labels, tags and notes are stored in app data. Export writes a ZIP at the location you choose. | Remove the preserved copy or export, or clear the annotation. An overwritten rolling replay can only be recovered if you already saved a copy. [Replay shelf](doctor-replays.md#replay-shelf) |
| **Backup & transfer** | Creating an archive reads the game. Restoring can write selected decks, replays, puzzles, screenshots and supported preferences in `config/system.conf`, plus selected files in the companion’s data folder. The preview shows conflicts before you choose what to keep. | Use the restore transaction to finish an interrupted restore or roll it back. Rollback restores the prior files and removes additions whose bytes still match the journal. It can stop if you have since edited a file. Keep the companion’s `restore-journals/` directory. [Backup engine](backup.md#restore-and-recovery) |
| **Health check** | Reads installation files and prepares the local report. | The check makes no game changes. [Installation doctor](doctor-replays.md#installation-doctor) |
| **On-demand content packs** | Browsing and downloading put files in the companion’s pack cache. Applying or importing content follows the write rules for its feature. The separate legacy `--textures` option writes to the game’s `textures/`. | Clearing cached packs does not undo already-applied changes. Use the relevant feature’s restore action. Remove newly added legacy textures to undo them, or restore a separate copy for files replaced with `--force`. [Content pack reference](content-packs.md) |

## Recovering after an interruption

Use the same game folder and companion config that you used to apply the change. Legacy appearance, sleeve and sound undo files live in `extras-backups/` beside the active config. Keep the app data and the game’s hidden recovery folders until you have restored what you need. Journals can store the original files and the changes EDOPal expects to see. If a restore stops because a file was edited later, keep that edit separately before resolving the conflict. A lock file can remain on disk after the operation finishes. The operating system releases the lock when the process exits.

The [portable backup ZIP](backup.md#selection) covers selected personal files. The optional audio category currently includes only deck-editor and duel recordings in the personal library. Keep a separate copy of recordings for the other music moments, custom artwork, active playlists, installed assets and recovery journals if you need to reproduce the whole installation.
